# Journal — מסקנות שלב המחקר והתכנון

נכון ל־1 באוקטובר 2026. זהו תכנון בלבד; לא נכתב מימוש מוצר ולא הורצו ניסויי סוכנים.

## ההמלצה: MODIFY, ואז GO מותנה

יש סיבה לבדוק את הרעיון, אבל סביבת עבודה שמריצה Codex ו־Claude כבר אינה בידול מספק. Superset, Conductor, dev-3.0, Emdash ו־T3 Code מכסים חלק ניכר מהחוויה. גם זיכרון מתמשך כבר קיים אצל הספקים ובכלים כמו Engram ו־claude-mem. המחקר כלל תיעוד וקובצי ארכיטקטורה/מתאמים ממאגרים פתוחים, ולא רק עמודי שיווק. [מקורות ובדיקות](RESEARCH.md).

ההזדמנות האפשרית היא **ידע פרויקטלי שאפשר לסמוך עליו ולבדוק אותו**: מקור וראיות לכל טענה, היקף שמתאים לענף ולסביבת העבודה, בדיקת התיישנות מול הקוד הנוכחי, ותיעוד מדויק של מה שנמסר לכל סוכן ולמה. לא הוכח עדיין שהשילוב הזה עדיף על סביבת עבודה קיימת עם כלי זיכרון חיצוני.

## מגבלת אינטגרציה שאסור להתעלם ממנה

Codex מציע ממשק app-server מתועד, עם גבול שונה בין אפליקציה מקומית בקוד פתוח לבין שירות מסחרי/מאוחסן. ב־Claude, תיעוד Anthropic מגביל מוצרים של צד שלישי שמציעים התחברות או שימוש במכסת מנוי דרך SDK. הפעלת ה־CLI הקיים של המשתמש היא מסלול טכני אחר, אבל אינה הוכחה להיתר גורף. אין לבנות הבטחת מוצר סביב שימוש במנוי לפני בירור המסלול הזה. [Codex](https://learn.chatgpt.com/docs/app-server#authentication), [מדיניות SDK](https://code.claude.com/docs/en/agent-sdk/overview), [שימוש באימות](https://code.claude.com/docs/en/legal-and-compliance).

החלופה הברורה ל־SDK היא API בתשלום נפרד לספק. חלופת CLI יכולה לשמר חוויית טרמינל, עם תצפית חלקית ולא הבטחה לשיחה ול־trace מלאים. אין לחלץ טוקנים או להסתמך על מה שמתחרים עושים כהוכחת הרשאה.

## מה הייתי בונה קודם

קודם ניסוי זמני בשני הסוכנים, ב־Mac וב־Windows מקומי: התחלה, הקשר, אישור/סירוב פעולה, שינוי קובץ ובדיקות, עצירה וחידוש. אחריו מאגר אחד, סשן אחד, זיכרונות שמאושרים ידנית ומקושרים לראיות, חיפוש טקסטואלי ו־Context Inspector. המבחן הראשון הוא ידע שנלמד בעבודה עם Codex ונמסר ל־Claude שבוחן את אותו מימוש.

המחסנית המוצעת: **Tauri 2, Rust, React/TypeScript/Vite ו־SQLite FTS5**, עם Git CLI, portable-pty ו־xterm.js. אם עלות גשר SDK ואריזת התהליכים מבטלת את היתרון, Electron הוא חלופה רצינית. אין בסיס להבטיח יתרון ביצועים לפני מדידה.

## החלטות חשובות לגבי הזיכרון

- היסטוריית ריצה אינה זיכרון מתמשך. רוב הפלט לא יהפוך לידע עתידי.
- החלטות וסיבות שורש דורשות ראיות ואישור כשהמשמעות אינה חד־משמעית. בדיקות שעברו אינן הוכחה לסיבת שורש.
- כישלון נשמר עם תנאי הסביבה שבהם התרחש, ולא ככלל שאסור לנסות גישה מסוימת לעולם.
- ידע מענף ניסיוני אינו אמת של כל המאגר. קידום שלו דורש בדיקה ואישור מתאים.
- טענה מיושנת או סותרת נפסלת מהזרקה אוטומטית עד בירור. נעילה/חשיבות אינן עוקפות בדיקת תוקף.
- MVP מתחיל בלי embeddings ובלי מסד וקטורי. תקציב ההקשר קטן, והמשתמש יכול לבדוק כל פריט שנבחר.

## מה לא לבנות עכשיו

לא IDE, לא לוח משימות, לא מערכת Git מלאה, לא framework תוספים גדול, לא ענן ולא דירוג איכות סוכנים. גם לא תצוגה שמתיימרת לחשוף reasoning פנימי או את מלוא הקשר המודל. הצפנה של SQLite אינה מובטחת ב־MVP; נתוני ספק והיסטוריה שלו אינם בשליטת Journal.

**שם המוצר עודכן ל־Journal לבקשת המשתמש.** השם הקודם, Blackbox, הוחלף; המחקר המקורי הצביע על התנגשות עם BLACKBOX AI בתחום סוכני הקוד. לא בוצעה בדיקת זמינות או סימן מסחר לשם Journal. [המוצר הקיים בשם הקודם](https://www.blackbox.ai/agents).
